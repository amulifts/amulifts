# Authenticated profile stats

The README displays SVGs generated by **Update README stats** every six hours
and on manual dispatch. Until the first successful run, the cards show an
explicit pending message. Failed generation preserves the last committed cards.
The existing streak card and snake workflow are independent and unchanged.

## Activate

1. Merge/push this change to `main`.
2. Create a classic GitHub PAT with `repo` and `read:user` scopes, as documented by
   [the generator](https://github.com/stats-organization/github-readme-stats-action#inputs).
   Set an expiration and authorize organization SSO if required. Organization
   policy may prohibit classic PATs or access to particular repositories.
3. In this repository, open **Settings → Secrets and variables → Actions → New
   repository secret**. Name it **STATS_PAT** and paste the PAT as its value.
   Do not put it in the README, workflow, image URLs, or chat.
4. Open **Actions → Update README stats → Run workflow**, selecting `main`.
5. Confirm both generation steps and the commit step succeed, and check the two
   SVGs in `profile/`. GitHub may briefly cache the previous README images.

The PAT reads stats; the repository's automatic `GITHUB_TOKEN` commits the SVGs.
Repository/organization Actions policy must allow the pinned third-party action
and `contents: write`. If branch protection blocks direct bot commits, adjust the
publication workflow to your repository's review policy; do not bypass protection.
When the PAT expires, replace the secret and rerun the workflow.

## What these numbers mean

Authentication includes private data accessible to the token. Public SVGs expose
aggregate statistics and language totals; they do not include repository names
or source code. Only generated SVGs are committed.

This is not a guarantee of every activity across all repositories. The generator
uses GitHub's API counting rules: commit counts and contribution-calendar totals
are different metrics. The language card covers up to 100 non-fork repositories
owned by the profile account, including accessible private repositories; it is
based on language bytes, not time spent or proficiency. It does not represent
all organization repositories to which the account contributes. Star pagination
is enabled. Access restrictions, SSO, and GitHub API limits still apply.

Fine-grained PATs have different coverage and may omit private commit statistics;
use the generator's documented classic-token configuration for this workflow.

## Combined contribution snake

`Generate Snake` now sums daily calendar counts over the last 365 UTC dates from
GitHub `amulifts`, GitHub `amankworks`, and GitLab `amankworks`, then uses the
pinned Platane/snk solver and SVG renderer to animate the merged calendar. Both
README snake SVGs are published to the existing `output` branch. The previous GIF
is retained but no longer refreshed; the README uses SVGs only.

- `STATS_PAT` reads the primary GitHub account.
- Optional `AMANKWORKS_PAT` reads the second GitHub account's private activity.
  Create it while signed into GitHub `amankworks` and save it as a repository
  Actions secret here. Without it, the automatic GitHub token reads the calendar
  visible to that token, including any publicly displayed private-activity totals.
- GitLab uses its public `/users/amankworks/calendar.json` calendar. No GitLab
  token is required, and hidden private events are not fetched.

A failed source stops publication and preserves the existing animation. Counts
are summed by date, with intensity scaled to the highest merged daily count.
They represent each platform's calendar activity, not just commits. Mirrored
activity can count on both platforms; aggregate calendars cannot deduplicate it.
This does not change the stats cards, streak card, or GitHub's native graph.
